# 7z 哈希对比工具

调用系统里已有的 **7-Zip** 批量计算文件哈希（SHA-256 / MD5 / SHA-1 / SHA-512 …），
并把「哪些文件内容相同」这件事一眼看清：相同哈希自动同色分组、选中即可给出结论、
还能贴一个官方校验值逐行比对。

零第三方依赖：Python 自带 tkinter + 系统里的 7-Zip，不内置任何二进制。

---

## 一、运行环境

| 项目 | 要求 |
| --- | --- |
| Python | 3.9+，且带 tkinter（Windows 官方安装包默认带） |
| 7-Zip | 任意较新版本（实测 26.00）。**不需要**加进 PATH，见「五」 |

## 二、启动

```bat
run.bat                          :: 双击即可
python main.py                   :: 或命令行启动
python main.py a.iso b.iso c.iso :: 启动并预加载文件（目录会自动展开）
python main.py --run a.bin b.bin :: 预加载后立即开始计算
python main.py --7z "D:\7-Zip\7z.exe" a.bin
```

### 挂到资源管理器右键（发送到）

双击 `install-sendto.bat`，之后在资源管理器里**选中任意多个文件/文件夹**
→ 右键 → **发送到 → 7z 哈希对比**，工具会一次收到全部路径、自动展开文件夹并开始计算。

- 只往 `%APPDATA%\Microsoft\Windows\SendTo` 放一个 `.lnk`，**不写注册表、不需要管理员**；
  卸载双击 `uninstall-sendto.bat`（或直接删掉那个快捷方式）。
- 为什么走「发送到」而不是自定义右键项：经典右键菜单（`HKCU\...\shell\...`）
  拿不到"多选的全部文件"，`%1` 只有第一个，多选时 Shell 会**对每个文件各启动一次进程**
  （表现为弹一堆窗口）。真正支持多选传参的标准路子只有自写 `IContextMenu` COM 扩展，
  或者用「发送到」——后者会把所有选中项作为一次调用的多个参数传进来。
- 想换菜单名：`powershell -File install-sendto.ps1 -Name "哈希对比"`。

## 三、三步用法

1. **添加文件**：`添加文件…` 或 `添加文件夹…`（可勾选「含子文件夹」）。
2. **勾选算法** → 点 `▶ 计算哈希`。多算法只跑一次 7z 进程，不是逐个算法重算。
3. **看结果**：内容相同的文件被染成同一底色，「标记」列写明 `组 1 · 3 个相同`。

## 四、对比功能

- **重复分组**：按主算法（算出结果最多的那个）把相同哈希归组并着色，汇总栏报告
  `N 组重复（涉及 M 个文件）`。
- **选中即对比**：在表格里多选 2 个以上文件，下方结论框立刻给出
  `结论：内容一致 ✅` 或 `存在差异 ❌`，并按算法分别说明有几种不同值。
- **参考值校验（支持部分匹配）**：粘贴官方发布的哈希，逐行标记并高亮。
  完整值、只记得开头几位、或只有中间一段片段都能定位到文件：

  | 输入 | 「参考」列 | 行底色 |
  | --- | --- | --- |
  | 完整哈希 | `✓ 相同` | 绿色 |
  | 前缀片段（≥4 位） | `◐ 前缀 SHA-256` | 琥珀色 |
  | 中间片段（≥4 位） | `≈ 包含 MD5` | 琥珀色 |
  | 有输入但无命中 | `✗ 未命中` | 保持分组色 |
  | 少于 4 位 | 不标记 | —（汇总栏提示「参考值太短」） |

  算法范围可选某个算法或「全部算法」——只有一小段片段、不记得它是哪种算法算的时，
  选「全部算法」直接告诉你命中在哪一列。输入过程中即时刷新，旁边有「清空」按钮。
  之所以设 4 位下限：3 个十六进制字符在 64 位哈希里命中是大概率事件，标出来只会误导。

  以下粘贴写法都会判成「完全一致」（大小写不敏感）：

  ```
  44159F63…      0x44159f63…      "44159f63…"\n      sha256=44159f63…
  4415 9f63 cbf3 …      44:15:9f:63:…      44-15-9f-63-…
  44159f63…  文件名.bin            ← sha256sum 整行，自动忽略后面的文件名
  ```
- **只看重复**：一个勾选框过滤掉唯一文件，几万行的文件夹里只留可疑对象。
- **显示完整哈希**：默认只显示前 16 位（列宽不至于把 64 位截断），勾上后按位数留宽。
- **哈希大小写**：`大写 / 小写` 单选，切换后表格、复制、TXT/CSV 导出一起跟着变。
  内部一律按大写存、比对也两边转大写，所以**这个开关只影响显示，不影响任何匹配结果**
  ——切到小写后贴大写的官方校验值照样精确命中。选小写的好处是能直接和
  `sha256sum` / `.sha256` 清单文件的排版对齐，方便肉眼核对与 diff。
- **多算法交叉校验**：同一组文件若 SHA-256 相同而 MD5 不同（数据被动过、
  或其中一个算错），标记列会显示 `⚠ 算法结果不一致`，汇总栏单独计数。
- **点列头排序**：点 SHA-256 列头即可把相同哈希排到一起，便于人工核对。
- **实时进度**：进度条按**字节加权**走动（不是按"完成文件数"），单个 3.7 GB 文件
  也能看到 0% → 100% 平滑推进，状态栏同时显示当前文件、已完成个数和预计剩余时间。
  实现上靠 `7z` 的 `-bsp1` 开关——不加它，7z 在输出被重定向时根本不报进度，
  整个表要等算完才一次性刷出来，单文件就表现为"进度条一直 0% 然后瞬间 100%"。
- **导出报告**：TXT（按文件分段的清单）或 CSV（带 BOM，Excel 直接打开不乱码）。
- **右键菜单**：复制哈希、复制「文件名 + 哈希」、在资源管理器中显示、只重算该文件。
  双击行 = 在资源管理器中定位该文件。

## 五、7-Zip 的查找顺序

程序按下面顺序找，找到能跑的第一个就用；也可以在界面上点「指定 7z.exe」手动选择，
选完记在 `settings.json` 里，**不需要把 7-Zip 加进系统 PATH**：

1. 环境变量 `HASHGUI_7Z`（或命令行 `--7z`）
2. `PATH` 里的 `7z` / `7za`
3. 常见安装目录：`D:\ProgramFiles\7-Zip`、`C:\Program Files\7-Zip`、
   `C:\Program Files (x86)\7-Zip` 等
4. 注册表 `App Paths\7zFM.exe` 指向的安装目录
5. `PATH` 里的 `7zr`（精简版同样支持 `h` 命令，算哈希够用）

每个候选都会真跑一次 `-h` 验证，避免把同名残留当成 7-Zip。

## 六、支持的算法

| 算法 | 开关 | 十六进制长度 | 说明 |
| --- | --- | --- | --- |
| SHA-256 | `-scrcSHA256` | 64 | 默认勾选，目前最常用 |
| MD5 | `-scrcMD5` | 32 | 老下载站常用 |
| SHA-1 | `-scrcSHA1` | 40 | |
| SHA-512 | `-scrcSHA512` | 128 | |
| SHA-384 | `-scrcSHA384` | 96 | |
| CRC-32 | `-scrcCRC32` | 8 | 只能查损坏，不能防伪 |
| BLAKE2sp | `-scrcBLAKE2SP` | 128 | 需 7-Zip 21.01+ |

启动后会在后台探测本机 7-Zip 实际支持哪些，不支持的自动取消勾选并置灰。

## 七、实现上两个必须知道的坑

1. **中文文件名**：7-Zip 默认按控制台 OEM 码页输出（中文 Windows 是 GBK），
   用 UTF-8 解码会得到乱码、路径就对不回去。程序统一加 `-sccUTF-8`，
   并显式以 UTF-8 读取子进程输出。
2. **绝对路径会被削成文件名**：`7z h` 的 Name 列对绝对路径只回显文件名，
   不同目录下的两个 `setup.exe` 回显完全一样，结果只能靠猜。
   程序改为「按盘符分组 → 取最近公共祖先当工作目录 → 传相对路径」，
   7-Zip 就会原样回显相对路径，才能可靠对回去（见 `core/sevenzip.py::plan_batches`）。

另外：单条命令的路径总长度超过 14000 字符会自动拆批，避免撞上 Windows
命令行 32767 字符上限；计算过程逐行流式回填，所以大文件是边算边出结果，
不是等全部跑完才刷新。

## 九、自检

```bat
python selftest.py
```

会真实调用系统 7-Zip，并把每个哈希与 Python `hashlib` 独立算出的结果逐一比对，
覆盖：中文/空格路径、不同目录同名文件、不存在的文件、多算法一次跑完、
重复分组、参考值归一化、交叉矛盾、界面计算与着色、排序、TXT/CSV 导出、取消。
测试素材写在程序目录 `temp/` 下，跑完自动删除。

## 十、常见问题

**Q：没装 7-Zip 会怎样？**
A：启动时会在日志区给出明确提示和下载地址，界面按钮置灰；装好后点
「指定 7z.exe」选中安装目录里的 exe 立即可用，无需重启。

**Q：几百 GB 的文件算得动吗？**
A：算的是 7-Zip 自己的实现，实测 16MB 约 0.08s（SHA-256，含磁盘读）。
真正的大文件是磁盘顺序读带宽决定，界面会显示实时速度。

**Q：为什么有的文件标记是「✗ 未算出」？**
A：文件不存在、正被独占或路径太长（>260 字符且系统未开启长路径支持）。
日志区会打印 7-Zip 给出的原始原因。

**Q：7-Zip 自己右键的「CRC SHA」多选时是不是把文件合起来算了一个哈希？**
A：逐文件那几行是对的（实测与 `hashlib` 完全一致），但它底部还会多出一个**归档级汇总**：

```
SHA256 for data:            eade410a…-00000000
SHA256 for data and names:  549d7ad3…-00000001
```

这两个值不等于「把文件内容拼起来算哈希」（实测拼接真值是 `36a5b883…`，与它不同），
它是 7-Zip 把这一批文件当成一个归档、按自己的归档结构算出的整体校验值；
`-00000000` 那段后缀也不是哈希的一部分，复制去别处比对一定对不上。
只选 1 个文件时汇总行恰好等于该文件哈希且没有后缀，所以单选/多选看起来"格式不一样"。
换序重算验证过：汇总值不变（内部按条目规范化排序），但它依赖 7z 的实现，
不能当通用指纹。本工具的解析器要求「算法数 + Size + 文件名」三段齐全，
汇总行没有文件名列，天然被丢掉（自检有 `解析器只收数据行` 一条盯着它）。

**Q：能对比压缩包内部的文件吗？**
A：不能。本工具算的是磁盘上文件的哈希；`7z h` 对压缩包内条目另有语义，
不在这里混用，避免结果看起来一样其实口径不同。
